# فاز ۷ — رفتار انتخاب را با مدل React بساز

حالا سه کتاب داریم و می‌خواهیم حداکثر یکی انتخاب شود. انتخاب مجدد همان کتاب، انتخاب را پاک کند.
ورودی: کارت‌ها و props. خروجی: انتخاب هماهنگ کارت، خلاصهٔ انتخاب و پنل state.

## قبل از کدنویسی تصمیم بگیر

حداقل اطلاعات متغیر چیست؟ فقط شناسهٔ کتاب انتخاب‌شده یا null؛ لازم نیست آبجکت کتاب را جدا ذخیره کنیم.
چه کسی به آن نیاز دارد؟ هم کارت‌ها، هم خلاصه. پس state را در والد مشترک آن‌ها، App می‌گذاریم.

## ترتیب نوشتن

1. در App، useState را import کن و selectedId را با مقدار اولیهٔ null بساز.
2. selectedBook را با find از روی books و selectedId محاسبه کن؛ آن را state دوم نکن.
3. handleSelect را بنویس: انتخاب همان شناسه را null و انتخاب شناسهٔ دیگر را جایگزین کند.
4. به هر BookCard دو ورودی تازه بده: selected و onSelect.
5. در BookCard، onClick را به تابعی وصل کن که هنگام کلیک onSelect(book.id) را صدا می‌زند.
6. متن، className و aria-pressed را از روی selected توصیف کن؛ دستور تغییر مستقیم DOM ننویس.
7. خلاصهٔ انتخاب و پنل نمایش selectedId را در App اضافه کن.
8. قوانین ظاهری is-selected و پنل‌ها را به CSS اضافه کن.

## مسیر یک کلیک

کلیک در کارت → callback با شناسه → handleSelect در والد → درخواست تغییر state → render تازه → props تازه → DOM تازه.
callback به فرزند اجازه می‌دهد درخواست را اعلام کند؛ state همچنان در App مدیریت می‌شود.
setter متغیر محلی اجرای فعلی را فوراً بازنویسی نمی‌کند؛ React مقدار بعدی را در render بعدی به کار می‌گیرد.

## آزمایش و تمرین

پاسخ آماده: npm run dev -- 07. کتاب اول، سپس دوم را بزن؛ فقط دوم باید انتخاب باشد.
دوباره دوم را بزن؛ انتخاب باید خالی شود. پیام و selectedId باید با کارت هماهنگ بمانند.
Refresh کامل باید انتخاب را پاک کند. تمرین: قانون لغو انتخاب را حذف کن تا همان کتاب همیشه انتخاب بماند؛ سپس برگردان.

## معیار پایان

بتوانی بگویی چرا انتخاب در BookCard نگهداری نشده و فرق onSelect با onClick چیست.
با فاز ۳ مقایسه کن: آنجا خودمان متن و کلاس را تغییر می‌دادیم؛ اینجا از روی state نمایش را توصیف می‌کنیم.
قدم بعد: یک state مستقل برای عبارت جست‌وجو اضافه می‌کنیم.
