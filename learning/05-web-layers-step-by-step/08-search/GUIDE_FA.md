# فاز ۸ — قابلیت تازه را بر قابلیت قبلی سوار کن

هدف: جست‌وجوی عنوان یا موضوع کتاب‌ها، با حفظ انتخاب قبلی.
دو وضعیت مستقل داریم: چه چیزی جست‌وجو شده و کدام کتاب انتخاب شده است.

## ترتیب نوشتن

1. در App یک query با useState("") اضافه کن؛ selectedId را نگه دار.
2. یک label و input بساز؛ value را به query و onChange را به setter آن وصل کن.
3. از روی query، normalizedQuery را با trim و toLowerCase محاسبه کن.
4. با filter از books، visibleBooks را محاسبه کن؛ آن را state جدا نکن.
5. فقط منبع map و شمارنده را به visibleBooks تغییر بده؛ selectedBook باید همچنان از کل books پیدا شود.
6. وقتی visibleBooks خالی است، پیام نتیجهٔ خالی را با شرط JSX نمایش بده.
7. query را به پنل نمایش state اضافه کن و قواعد ظاهری input را بنویس.

BookCard، داده‌ها، تابع قیمت، main و HTML تغییری ندارند؛ قابلیت تازه عمدتاً مسئولیت App است.

## چرا visibleBooks را ذخیره نمی‌کنیم؟

از دادهٔ ثابت و query قابل محاسبه است. اگر هم query و هم آرایهٔ فیلترشده را ذخیره کنیم، باید همیشه هماهنگشان نگه داریم.
filter و includes ابزار JavaScript هستند. useState ابزار React است. JSX نتیجهٔ محاسبه را توصیف می‌کند.

## آزمایش

پاسخ آماده: npm run dev -- 08. عبارت React باید یک کارت نشان بدهد؛ nothing-here باید پیام خالی نشان بدهد.
ورودی را پاک کن؛ سه کارت برمی‌گردند. قبل از جست‌وجو کتابی را انتخاب کن و سپس پنهانش کن.
خلاصهٔ انتخاب باید باقی بماند؛ پنهان‌شدن کارت به معنی پاک‌شدن selectedId نیست.
تمرین: جست‌وجو را فقط به عنوان محدود کن، آزمایش کن و سپس جست‌وجوی موضوع را برگردان.

## معیار پایان

بتوانی دو state را نام ببری و توضیح بدهی visibleBooks و selectedBook چرا state نیستند.
قدم بعد: همین رفتار کاربر را نگه می‌داریم و قراردادهای TypeScript اضافه می‌کنیم.
