# فاز ۶ — یک مسئولیت را به کامپوننت جدا بده

ورودی و خروجی ظاهری هر دو سه کارت‌اند. این مرحله قابلیت تازهٔ کاربری ندارد؛ ساختار کد را بهتر می‌کنیم.
App صاحب فهرست است و BookCard مسئول توصیف نمایش یک کتاب می‌شود.

## ترتیب نوشتن

1. src/BookCard.jsx را بساز. JSX یک article را از App به آن منتقل کن.
2. تابع BookCard ورودی book را از props بگیرد؛ اطلاعات کتاب را داخل آن دوباره تعریف نکن.
3. import تابع formatPrice را به BookCard منتقل کن، چون حالا نمایش قیمت مسئولیت این فایل است.
4. در App، BookCard را import کن و داخل map به هر نمونه، book همان دور را بده.
5. key را روی BookCard درون map بگذار؛ دیگر article داخلی محل تشخیص عضو فهرست نیست.
6. فایل‌های index.html، main.jsx، داده‌ها و CSS را دست نزن؛ رفتارشان تغییر نکرده است.

## props یعنی چه در این مسئله؟

book ورودی یک نمونهٔ کامپوننت است. یک تعریف BookCard داریم، ولی برای سه کتاب از آن استفاده می‌کنیم.
نام book را خودمان انتخاب کرده‌ایم. همان آبجکت داده از App به فرزند می‌رسد.
فرزند نباید دادهٔ ورودی را مستقیم تغییر دهد. این مرحله هنوز state و انتخاب ندارد.

## آزمایش

پاسخ آماده: npm run dev -- 06. باید همان سه کارت فاز ۵ را ببینی.
یک جمله در BookCard اضافه کن؛ جمله روی همهٔ کارت‌ها ظاهر می‌شود.
سپس فقط عنوان یک عضو books.js را تغییر بده؛ فقط همان کارت تغییر می‌کند.

## معیار پایان

بتوانی از روی کد مسیر books → map در App → prop به BookCard → متن داخل کارت را دنبال کنی.
این یک بازآرایی است: نتیجهٔ ظاهری ثابت می‌ماند و محل مسئولیت‌ها روشن‌تر می‌شود.
قدم بعد: در App یک انتخاب مشترک نگه می‌داریم و از کارت با callback خبر می‌گیریم.
