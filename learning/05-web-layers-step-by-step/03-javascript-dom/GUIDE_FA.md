# فاز ۳ — از عنصر موجود به رفتار قابل مشاهده برس

ورودی: یک کارت ظاهرگرفته. خروجی: انتخاب و لغو انتخاب همان کتاب با کلیک.
این فاز نسخهٔ JavaScript مستقیم را می‌سازد تا بعداً دلیل تغییر روش در React را درک کنی.

## ترتیب نوشتن

1. به دکمهٔ HTML ویژگی aria-pressed="false" اضافه کن و بعد از کارت یک پیام با id="selection-summary" بگذار.
2. در src/main.js دکمه، کارت و پیام را با getElementById پیدا کن. idها باید با HTML یکی باشند.
3. نبودن عنصرها را بررسی کن؛ اگر ساختار اشتباه باشد، خطای روشن بده.
4. یک متغیر selected با مقدار false بساز؛ حافظهٔ سادهٔ این رفتار است.
5. با addEventListener تابع کلیک را ثبت کن؛ این تابع موقع کلیک اجرا می‌شود.
6. در تابع، مقدار انتخاب را برعکس کن و متن، ویژگی و کلاس DOM را با آن هماهنگ کن.
7. دو قانون is-selected را به CSS اضافه کن.
8. در انتهای body فایل index.html، فایل src/main.js را با script متصل کن.

ترتیب خواندن پاسخ: index.html، src/main.js، دو خط تازهٔ styles.css.

## چه کسی چه کاری می‌کند؟

JavaScript مقدار انتخاب را تغییر می‌دهد و دستور تغییر DOM می‌نویسد.
DOM وضعیت فعلی صفحه است. CSS با دیدن کلاس is-selected ظاهر انتخاب را اعمال می‌کند.
اگر یکی از دستورهای تغییر متن یا کلاس را جا بیندازی، خودت باید ناسازگاری نمایش را رفع کنی.

## آزمایش

پاسخ آماده: npm run dev -- 03. کلیک اول باید انتخاب کند؛ کلیک دوم باید آن را پاک کند.
با Refresh کامل، انتخاب پاک می‌شود چون ذخیرهٔ دائمی نداریم.
تمرین: یک پیام دیگر روی صفحه اضافه کن و هنگام کلیک آن را هم هماهنگ کن؛ تعداد دستورهای مستقیم را ببین.

## معیار پایان و دلیل قدم بعد

بتوانی مسیر کلیک → تغییر متغیر → تغییر متن و کلاس → ظاهر تازه را توضیح بدهی.
فاز ۴ یک بازسازی آگاهانه است: یک کارت ثابت را با React می‌نویسیم تا JSX و اتصال React را جدا بفهمیم.
بنابراین رفتار انتخاب فاز ۳ را فعلاً به نسخهٔ React منتقل نمی‌کنیم؛ آن را در فاز ۷ با state بازسازی می‌کنیم.
فاز ۳ برای مقایسه حفظ می‌شود و بعداً صفحهٔ direct-dom در نسخهٔ نهایی همین نقش را دارد.
