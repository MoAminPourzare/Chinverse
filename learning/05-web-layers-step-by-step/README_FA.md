# فروشگاه کتاب؛ این بار از صفحهٔ خالی تا مثال کامل

این پوشه همان مثال آموزشی `04-web-layers` را در ۱۰ نقطهٔ قابل اجرا بازسازی می‌کند.
هدف فقط شناختن فایل‌ها نیست؛ می‌خواهیم یاد بگیریم برنامه‌نویس در هر لحظه چه مسئله‌ای دارد، کدام فایل را می‌نویسد و چرا قدم بعدی لازم می‌شود.

از **راهنمای فاز ۱** شروع کن: [01-html/GUIDE_FA.md](01-html/GUIDE_FA.md).
خواندن کد نسخهٔ نهایی پیش‌نیاز شروع نیست. هر بار فقط راهنمای همان فاز و فایل‌های معرفی‌شدهٔ آن را باز کن.

## قبل از اولین فایل، مسئله را مشخص کن

برای این مثال درخواست ما این است: سه کتاب با عنوان، موضوع و قیمت نشان بده؛ کاربر بتواند یک کتاب انتخاب کند، انتخاب را لغو کند و عنوان یا موضوع را جست‌وجو کند.
روی کاغذ یک عنوان صفحه، یک ورودی جست‌وجو، یک خلاصهٔ انتخاب و سه کارت بکش. هر کارت یک عنوان، قیمت و دکمه دارد.
این تصویر، مقصد است؛ لازم نیست همهٔ آن را در اولین قدم بسازی. ابتدا فقط یک کارت ثابت را قابل مشاهده می‌کنیم.
بعد از اینکه ساختار کار کرد، ظاهر، داده و رفتارها را یکی‌یکی اضافه می‌کنیم.
قانون انتخاب را هم روشن می‌کنیم: حداکثر یک کتاب انتخاب می‌شود، کلیک دوباره انتخاب را پاک می‌کند و جست‌وجو انتخاب را از بین نمی‌برد.
در این تمرین خرید و پرداخت یا ذخیرهٔ دائمی نمی‌سازیم؛ پس نیازی نیست از طراحی دیتابیس شروع کنیم.

## اولین اجرا

در ترمینال VS Code:

```powershell
cd E:\Chinverse\learning\05-web-layers-step-by-step
npm run dev -- practice
```

بعد http://127.0.0.1:4174/ را باز کن. این آدرس به سرور توسعه روی کامپیوتر خودت وصل می‌شود.
فعلاً پیام شروع میز کار را می‌بینی؛ محتوای آن را طبق راهنمای فاز ۱ با کد خودت جایگزین می‌کنی.
سرور را هنگام تمرین باز نگه دار. برای توقف Ctrl+C بزن.

برای مشاهدهٔ پاسخ یک فاز، سرور را متوقف کن و مثلاً این دستور را اجرا کن:

```powershell
npm run dev -- 01
```

شماره را به 02 تا 10 تغییر بده تا همان نسخه اجرا شود. آدرس همهٔ نسخه‌ها یکسان است؛ **پوشهٔ فعال با دستور انتخاب می‌شود، نه با افزودن شماره به URL**.
دستور بدون آرگومان، `practice` را اجرا می‌کند. فقط پوشه‌ای را ویرایش کن که مسیرش در ترمینال به‌عنوان پوشهٔ فعال چاپ شده است.

این درس از React، React DOM، TypeScript و Vite موجود در `frontend/node_modules` استفاده می‌کند؛ اینجا `npm install` لازم نیست.
این پوشه به‌تنهایی یک بستهٔ قابل انتقال با همهٔ وابستگی‌ها نیست؛ داخل همین مخزن اجرا می‌شود.
پورت درس قبلی 4173 و پورت این درس 4174 است. اگر 4174 اشغال باشد، برنامه خطا می‌دهد و خودسرانه پورت دیگری انتخاب نمی‌کند.

## روش کار در هر فاز

1. فقط بخش «هدف» راهنمای فاز را بخوان و بگو خروجی قابل مشاهده چه باید باشد.
2. از روی بخش «ترتیب نوشتن»، فایل‌ها را یکی‌یکی در `practice` بساز یا تغییر بده.
3. بعد از هر تغییر کوچک، نتیجه را در مرورگر ببین. لازم نیست ابتدا همهٔ فایل‌های فاز را تمام کنی.
4. اگر گیر کردی، فقط فایل همان قدم را در پاسخ آماده باز کن.
5. بخش آزمایش و تمرین را انجام بده؛ صرف دیدن صفحه معیار پایان نیست.
6. وقتی توانستی مسئولیت فایل‌ها و مسیر داده را توضیح بدهی، به فاز بعد برو و همان `practice` را ادامه بده.

در هر فاز `CHANGES.diff` هم وجود دارد و دقیقاً تفاوت کد با پاسخ فاز قبلی را نشان می‌دهد.
خط‌های دارای `+` اضافه و خط‌های دارای `-` حذف شده‌اند؛ خود این فایل وارد اجرا نمی‌شود.
تغییرهای تمرینیِ دلخواهت در این مقایسه نیستند. اگر ظاهر پاسخ با تمرین فرق کرد، اول تغییرهای خودت را بررسی کن.
ترتیب نوشتن از راهنماست؛ ترتیب الفبایی فایل‌ها در VS Code، ترتیب ساخت یا اجرا نیست.

## ابزارهای آماده چه می‌کنند؟

| فایل | نقش |
| --- | --- |
| `package.json` | ثبت دستورهای dev و check برای npm |
| `phases.mjs` | فهرست فازها و انتخاب پوشهٔ فعال |
| `dev.mjs` | بررسی اولیه، راه‌اندازی Vite و تولید خروجی مقایسه در فاز نهایی |
| `check.mjs` | بررسی نحو در فازهای JavaScript و بررسی کامل نوع در فازهای دارای tsconfig |
| `.gitignore` | کنارگذاشتن کش و فایل‌های generated از نسخه‌برداری Git |

ابزارهای آماده از کد برنامه جدا هستند. پس از فهم ساخت مثال، می‌توانی برگردی و نحوهٔ ساخت همین ابزارها را هم بررسی کنی.
این ابزارها هنگام ویرایش، بررسی نوع دائمی انجام نمی‌دهند؛ بررسی مستقل را با دستور زیر اجرا کن:

```powershell
npm run check -- practice
npm run check -- 09
npm run check
```

دستور آخر همهٔ پاسخ‌های شماره‌دار را بررسی می‌کند؛ فایل‌های تمرین خودت در آن وارد نمی‌شوند.
در فازهای قبل از ۹، خروجی بررسی نحو به معنی تضمین سازگاری نوع‌ها نیست.
برای دیدن خطای TypeScript بدون ویرایش سورس:

```powershell
npm run check -- 09 --demo-error
```

شکست این آزمایش عمدی است. در فاز نهایی، `generated/` فقط هنگام شروع ساخته می‌شود؛ پس از تغییر سورس برای تازه‌کردن مقایسه، سرور را دوباره اجرا کن.

## چرا این ترتیب را انتخاب کردیم؟

ابتدا یک خروجی کوچک قابل مشاهده می‌سازیم، سپس یک مسئولیت تازه به آن اضافه می‌کنیم.
جداکردن کارت در فاز ۶ رفتار جدیدی ایجاد نمی‌کند؛ تمرین بازآرایی کد است. TypeScript در فاز ۹ هم عمداً ظاهر را عوض نمی‌کند.
در پروژهٔ کاری می‌توان از همان ابتدا TypeScript و ساختار کامپوننتی را انتخاب کرد؛ این ترتیب یک روش آموزشی برای دیدن اثر هر لایه است، نه قانون اجباری تمام پروژه‌ها.
ابتدا رابط ثابت، سپس داده و در پایان تعامل را جدا بررسی می‌کنیم؛ این بخش از رویکرد با [راهنمای رسمی Thinking in React](https://react.dev/learn/thinking-in-react) همسو است.
JSX و React دو مفهوم جدا هستند؛ برای توضیح مستقل آن‌ها [راهنمای JSX](https://react.dev/learn/writing-markup-with-jsx) مرجع تکمیلی است.

در پایان این مسیر، مثال محلی کامل است؛ سرور توسعه خروجی انتشار تولید نمی‌کند.
دیتابیس، API، حساب کاربری، پرداخت و Next.js در این تمرین وارد نشده‌اند؛ آن‌ها را بعداً در آموزش پروژهٔ اصلی اضافه می‌کنیم.
