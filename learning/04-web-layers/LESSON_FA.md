# درس کاربردی: مسئولیت لایه‌های وب در همین مثال

این راهنما ادامهٔ آموزش مستقل است. هدف، تشخیص سهم هر فناوری در یک برنامهٔ واحد است؛ آشنایی عمومی با برنامه‌نویسی فرض می‌شود. سورس این درس از برنامهٔ چین‌ورس جداست و اطلاعات آن ساختگی است.

## اجرا و مشاهده

```powershell
node E:\Chinverse\learning\04-web-layers\dev.mjs
```

نشانی: `http://127.0.0.1:4173/`. در نشست آموزشی ۲۲ اکتبر ۲۰۲۶ این نمونه اجرا و انتخاب، جست‌وجو، نتیجهٔ خالی، نمای DOM، خروجی تبدیل‌شده و صفحهٔ بدون React بررسی شدند. وضعیت مرورگر و سرور ممکن است در نشست بعدی برقرار نباشد؛ در صورت نیاز دستور بالا را دوباره اجرا کن. نصب وابستگی تازه لازم نیست؛ نمونه از بسته‌های موجود فرانت استفاده می‌کند.

اول روی انتخاب کتاب React بزن و تغییر `selectedId` را ببین. سپس «خواندن DOM» را بزن. این نما متن حاصل از خواندن DOM در همان لحظه است؛ پس از تغییر انتخاب باید دوباره خوانده شود.

## یک برنامه، چند مسئولیت

| فناوری | مسئولیت در این نمونه | نمونهٔ فایل |
| --- | --- | --- |
| HTML | سند اولیه و محل ریشهٔ رابط | `index.html` |
| CSS | ظاهر، چیدمان، رنگ و واکنش به کلاس‌ها | `src/styles.css` |
| JavaScript | منطق اجرایی، handler، فیلتر و قالب‌بندی قیمت؛ خود کتابخانه‌ها هم کد JavaScript دارند | `src/format-price.js` و منطق داخل TSX |
| TypeScript | بررسی ایستای قرارداد داده‌ها و ورودی/خروجی تابع‌ها | `src/types.ts` و annotationها |
| JSX | نحو توصیف ساختار رابط درون کد؛ پیش از اجرا تبدیل می‌شود | بخش return در کامپوننت‌ها |
| React | مدیریت state و محاسبهٔ ساختار کامپوننت‌ها و رابط | `src/App.tsx` |
| React DOM | اتصال خروجی React به DOM مرورگر | `src/main.tsx` |
| DOM | ساختار زندهٔ سند در حافظهٔ مرورگر | قابل مشاهده در Inspector |
| Vite | سرو فایل‌های توسعه، تبدیل نحو و حل importها | راه‌اندازی در `dev.mjs` |
| Node.js | محیط اجرای ابزارهای توسعه روی کامپیوتر | اجرای `dev.mjs` و `check.mjs` |

این‌ها مراحل کاملاً جدا و پشت‌سرهم در یک زنجیرهٔ ساده نیستند. HTML و CSS ورودی مرورگرند؛ TypeScript و JSX روی شکل سورس و تبدیل/بررسی آن اثر دارند؛ React و React DOM هنگام اجرا با کد JavaScript کار می‌کنند. Next.js در این مثال استفاده نشده است.

## از شروع برنامه تا اولین نمایش

۱. `dev.mjs` در Node.js اجرا می‌شود. ابتدا `check.mjs` بررسی نوع را انجام می‌دهد. اگر خطا باشد شروع متوقف می‌شود.
۲. خروجی آموزشی دو فایل TSX در `generated/` ساخته می‌شود. این نسخه برای مقایسهٔ متنی در Inspector است.
۳. سرور توسعهٔ Vite روی پورت ۴۱۷۳ فایل‌ها را در دسترس مرورگر قرار می‌دهد.
۴. مرورگر `index.html` را می‌خواند. در آن `<div id="root"></div>` و ارجاع به `/src/main.tsx` هست.
۵. Vite درخواست فایل TSX را تبدیل می‌کند و JavaScript مناسب اجرا به مرورگر می‌دهد؛ پسوند داخل URL به معنی اجرای مستقیم نوع‌های TypeScript و JSX توسط مرورگر نیست.
۶. `main.tsx` گرهٔ root را پیدا می‌کند و با `createRoot(container).render(<App />)` مدیریت محتوای آن را به React DOM می‌سپارد.
۷. React برای App و فرزندان، توصیف رابط را محاسبه می‌کند؛ React DOM گره‌های لازم را ایجاد می‌کند؛ مرورگر با قواعد CSS نمایش را رسم می‌کند.

این نمونه یک برنامهٔ سمت مرورگر است. سرور توسعه، بک‌اند تجاری یا محل ذخیرهٔ انتخاب‌ها نیست. در اجرای واقعی، فایل‌های سرو‌شده و بسته‌بندی می‌توانند شکل متفاوتی داشته باشند.

## HTML، JSX و DOM سه چیز متفاوت‌اند

HTML اولیه فقط ریشه و script این برنامه را دارد؛ کارت‌ها بعداً ساخته می‌شوند.

در TSX می‌نویسیم:

```tsx
<h3>{book.title}</h3>
```

خروجی آموزشی با تنظیم فعلی TypeScript شبیه این است:

```js
_jsx("h3", { children: book.title })
```

این فراخوانی یک توصیف React می‌سازد، نه اینکه همان‌جا `document.createElement` را مستقیم انجام بدهد. سپس React DOM از توصیف‌ها برای ساخت یا به‌روزرسانی سند استفاده می‌کند. نمای متنی گرهٔ ساخته‌شده می‌تواند این باشد:

```html
<h3>ساخت رابط با ری‌اکت</h3>
```

DOM خود رشتهٔ بالا نیست؛ گره‌های زندهٔ سند است. Inspector با `outerHTML` یک نمایش متنی از آن می‌گیرد. `className` در JSX به `class` در خروجی HTML مربوط می‌شود. `onClick` یک تابع JavaScript است و الزاماً به‌صورت ویژگی متنی onclick در outerHTML دیده نمی‌شود. `key` هم ویژگی DOM یا prop معمولی کامپوننت نیست.

## داده و قرارداد داده

`types.ts` قرارداد Book را تعریف می‌کند: id، title و topic رشته‌اند و price عدد است. این interface کتاب نمی‌سازد و پاسخ API را خودکار اعتبارسنجی نمی‌کند.

`books.ts` آرایهٔ واقعی همین مثال را می‌سازد. در `books: Book[]` بخش نوعی حذف می‌شود، اما آرایه، مقدار قیمت و عنوان‌ها در کد اجرایی باقی می‌مانند.

`format-price.js` یک تابع JavaScript معمولی با `Intl.NumberFormat("fa-IR")` است. این تابع عدد را برای نمایش به متن تبدیل می‌کند؛ نه JSX تولید می‌کند، نه state دارد و نه قیمت اصلی را عوض می‌کند. JSDoc آن برای ابزار بررسی نوع است، دستور اجرایی نیست. تنظیم `allowJs/checkJs` باعث می‌شود فایل JS هم در بررسی نوع این نمونه مشارکت کند.

## یک فایل TSX شامل چند نوع کد است

در `BookCard.tsx`:

- import نوع و `interface BookCardProps` مربوط به بررسی TypeScript است.
- خود تابع، دسترسی به ویژگی‌ها، شرط و callback کد اجرایی JavaScript هستند.
- `<article>` و تگ‌های return، JSX هستند.
- `useState` یا مفهوم کامپوننت متعلق به مدل و API React است؛ کارکرد آن‌ها با JavaScript پیاده شده.

پس فایل TSX زبان کاملاً جداگانه‌ای از JavaScript نیست؛ سورس TypeScript است که JSX هم در آن مجاز است.

این مثال عمداً سورس TSX را برای نمایش در Inspector به‌صورت متن هم بارگذاری می‌کند. بنابراین «حذف نوع‌ها از کد اجرایی» به معنی ناممکن‌بودن دیدن سورس یا نوع‌ها در مرورگر نیست. نباید اطلاعات محرمانه را در سورس فرانت گذاشت.

## مسیر یک کلیک، دقیق و پیوسته

در App، `selectedId` ابتدا null است. برای هر کتاب این prop محاسبه می‌شود:

```tsx
selected={book.id === selectedId}
```

کارت React در ابتدا selected=false می‌گیرد. `BookCard` هم دادهٔ کتاب و تابع `handleSelect` والد را از props می‌گیرد.

در کارت:

```tsx
onClick={() => onSelect(book.id)}
```

callback اکنون ثبت شده و هنگام کلیک اجرا می‌شود. `onSelect(book.id)` را همان موقع render صدا نزده‌ایم. برای کارت React شناسهٔ `react` به تابع والد می‌رسد.

در App:

```tsx
setSelectedId((current) => current === bookId ? null : bookId);
```

این یک updater است. اگر همان کتاب قبلاً انتخاب شده، انتخاب پاک می‌شود؛ وگرنه شناسهٔ تازه انتخاب می‌شود. setter مقدار محلی اجرای فعلی را عوض نمی‌کند؛ برای render بعدی تغییر state را ثبت می‌کند.

در اجرای بعدی App، کارت React مقدار selected=true می‌گیرد. JSX این بار کلاس `book-card is-selected`، متن «انتخاب شده ✓» و aria-pressed=true را توصیف می‌کند. React DOM تغییرهای لازم را اعمال می‌کند. CSS از روی کلاس تازه، رنگ مناسب را تعیین می‌کند.

`selected` و `onSelect` نام‌های انتخابی ما برای props هستند. `onClick` روی button جزو API رویداد React برای عنصر DOM است. CSS هیچ اطلاعی از متغیر selectedId ندارد؛ فقط کلاس‌ها و ساختار سند را می‌بیند.

## جست‌وجو: محاسبهٔ دادهٔ مشتق‌شده

در input، `value={query}` مقدار نمایشی را از state می‌گیرد. `onChange` متن ورودی را می‌خواند و setter را صدا می‌زند. تابع‌های trim، toLowerCase، includes و filter همگی JavaScript هستند.

`visibleBooks` با فیلترکردن books از روی query محاسبه می‌شود. خودش state نیست؛ در هر render از دادهٔ موجود به دست می‌آید. `selectedBook` هم از selectedId محاسبه می‌شود.

به همین دلیل، اگر کتاب انتخاب‌شده را با جست‌وجو از فهرست پنهان کنی، عنوان انتخاب بالای صفحه می‌ماند: query تغییر کرده، selectedId تغییر نکرده و selectedBook از کل books پیدا می‌شود.

با Refresh کامل state به مقدار اولیه برمی‌گردد. بدون localStorage، سرور یا دیتابیس، این انتخاب دائمی نیست. hidden شدن کارت هم با پاک‌شدن انتخاب والد یک چیز نیست.

## چرا React، وقتی بدون آن هم دکمه کار می‌کند؟

در `direct-dom.js` رویداد را با addEventListener می‌گیریم و سپس با textContent، classList و setAttribute، تغییر DOM را مستقیم می‌نویسیم. برای یک دکمه این روش کاملاً قابل استفاده است.

در نسخهٔ React، state و قوانین نمایش را تعریف می‌کنیم. یک انتخاب می‌تواند همزمان در کارت، خلاصهٔ انتخاب و بخش نمایش state اثر کند. React و renderer آن هماهنگی این خروجی‌ها با state را مدیریت می‌کنند. استفاده از React هزینهٔ کتابخانه و ابزار و یادگیری هم دارد؛ برای هر صفحهٔ ثابت الزام نیست.

## بررسی نوع با تبدیل سورس فرق دارد

```powershell
node E:\Chinverse\learning\04-web-layers\check.mjs
node E:\Chinverse\learning\04-web-layers\check.mjs --demo-error
```

دستور دوم در حافظه price را از عدد به رشته تغییر می‌دهد و خطای TS2322 تولید می‌کند. خروج ناموفق در این دستور عمدی است؛ سورس دست‌نخورده است. خود Vite بررسی نوع کامل انجام نمی‌دهد. در این درس، هنگام شروع سرور بررسی جدا اجرا می‌شود؛ پس از تغییر فایل‌ها نیز check را جدا اجرا کن.

`generated/` خروجی مقایسه‌ای TypeScript است و هنگام شروع سرور ساخته می‌شود؛ صفحهٔ اصلی آن فایل‌ها را به‌عنوان منطق برنامه اجرا نمی‌کند. اجرای اصلی با تبدیل Vite از سورس است. برای تازه‌کردن مقایسه پس از تغییر سورس، سرور را دوباره اجرا کن. خروجی ابزارها می‌تواند شامل helper و کد توسعهٔ متفاوت باشد.

## محل درست هر تغییر

| نیاز | محل شروع |
| --- | --- |
| تغییر عنوان یا قیمت یک کتاب | `books.ts` |
| تعریف یک ویژگی جدید و بررسی نوع آن | `types.ts` و در صورت نیاز قرارداد props |
| تغییر پیام یا ساختار یک کارت | `BookCard.tsx` |
| تغییر رنگ انتخاب | `styles.css` |
| تغییر قانون انتخاب یا فیلتر | `App.tsx` |
| تغییر قالب عدد قیمت | `format-price.js` |
| دیدن کد، خروجی تبدیل و DOM | ابزار `Inspector.tsx` و فایل‌های `generated` |

برای یک آزمایش کامل، ویژگی `description?: string` را به Book اضافه کن، در یک کتاب مقدار بده، در BookCard با `{book.description && <p className="book-description">{book.description}</p>}` نمایش بده و برای کلاس آن CSS تعریف کن. اضافه‌کردن ویژگی به نوع به‌تنهایی داده نمی‌سازد؛ اضافه‌کردن داده هم به‌تنهایی عنصر نمایشی نمی‌سازد؛ CSS نیز فقط عنصر موجود را سبک می‌دهد.

این درس نقش لایه‌های مثال را توضیح می‌دهد؛ به معنی تمام‌شدن آموزش JavaScript، TypeScript یا React نیست. بخش‌های شبکه، effect، سرور و Next.js جداگانه دنبال می‌شوند.
