# مثال مستقل: از کد تا صفحه

هدف این مثال روشن‌کردن مسئولیت JavaScript، TypeScript، JSX، React، React DOM، HTML، CSS و DOM است. محتوای این پوشه آموزشی است و وارد برنامه، routeها یا دیتابیس چین‌ورس نشده است.

راهنمای قدم‌به‌قدم و مسیر یک کلیک در [LESSON_FA.md](LESSON_FA.md) است. در ادامهٔ آموزش ۲۲ اکتبر ۲۰۲۶، نمونه با مرورگر بررسی شد؛ بررسی نوع موفق بود و آزمایش خطای عمدی نیز خطای مورد انتظار را بدون تغییر سورس نشان داد.

## اجرا

از هر مسیر:

```powershell
node E:\Chinverse\learning\04-web-layers\dev.mjs
```

سپس http://127.0.0.1:4173 را باز کن. توقف با Ctrl+C در ترمینال است. اگر پورت ۴۱۷۳ توسط برنامهٔ دیگری استفاده شود، سرور به‌جای جایگزین‌کردن آن خطا می‌دهد.

این نمونه از بسته‌های ازقبل‌نصب‌شدهٔ `frontend/node_modules` استفاده می‌کند؛ به نصب جدید یا `npm install` نیاز ندارد. مستقل‌بودن این درس به معنی جدابودن کد/مسیر اجرا از برنامه است؛ وابستگی‌های اجرایی را برای جلوگیری از نصب تکراری قرض می‌گیرد.

فقط بررسی نوع:

```powershell
node E:\Chinverse\learning\04-web-layers\check.mjs
```

برای دیدن خطای واقعی TypeScript بدون خراب‌کردن فایل‌های مثال:

```powershell
node E:\Chinverse\learning\04-web-layers\check.mjs --demo-error
```

این دستور فقط در نسخهٔ درون حافظهٔ کد، قیمت کتاب اول را رشته می‌کند. گزارش `Type 'string' is not assignable to type 'number'` و خروجی ناموفق در این آزمایش عمدی‌اند؛ فایل سورس و صفحهٔ در حال اجرا عوض نمی‌شوند.

## ترتیب مطالعهٔ فایل‌ها

| فایل | هدف |
| --- | --- |
| `index.html` | سند اولیه و جای شروع با `id="root"` |
| `src/types.ts` | قرارداد `Book` در TypeScript؛ خودش داده یا DOM نمی‌سازد |
| `src/books.ts` | دادهٔ ساختگی کتاب‌ها؛ آرایه در خروجی JavaScript می‌ماند ولی نوع آن حذف می‌شود |
| `src/format-price.js` | منطق اجرایی معمول JavaScript برای تبدیل عدد به متن قیمت |
| `src/BookCard.tsx` | تعریف نوع props، تابع کامپوننت و JSX یک کارت |
| `src/App.tsx` | state جست‌وجو و انتخاب، فیلترکردن، ترکیب کارت‌ها و دادن props |
| `src/main.tsx` | پیدا‌کردن ریشهٔ DOM و اتصال React DOM به آن |
| `src/styles.css` | رنگ، فاصله، چیدمان و ظاهر وضعیت انتخاب‌شده |
| `src/Inspector.tsx` | ابزار کمکی درس برای مقایسهٔ سورس، خروجی آموزشی JavaScript و DOM واقعی |
| `direct-dom.html` و `direct-dom.js` | همان ایدهٔ تغییر دکمه با HTML و JavaScript مستقیم، بدون React |
| `dev.mjs` و `check.mjs` | ابزار اجرای درس و بررسی نوع؛ جزو منطق فروشگاه نیستند |

## هر فناوری چه کاری انجام می‌دهد؟

- JavaScript: منطق فیلتر، رخداد کلیک، قالب‌بندی قیمت و کد اجرایی React و React DOM در مرورگر با JavaScript اجرا می‌شوند. فایل `.tsx` هم بخش زیادی منطق JavaScript دارد.
- TypeScript: سازگاری نوع داده و ورودی کامپوننت‌ها را هنگام توسعه بررسی می‌کند؛ `interface Book` و annotationهایی مانند `bookId: string` در خروجی اجرایی باقی نمی‌مانند. این قرارداد، اعتبارسنجی خودکار پاسخ شبکه نیست.
- JSX: نحو توصیف عناصر و ترکیب کامپوننت‌ها داخل کد است. `<h3>{book.title}</h3>` قبل از اجرا به فراخوانی JavaScript تبدیل می‌شود؛ رشتهٔ HTML یا خود گرهٔ DOM نیست.
- React: state را برای نمونه‌های کامپوننت نگه می‌دارد و با تغییر آن، نمایش جدید را محاسبه می‌کند.
- React DOM: renderer وب است؛ توصیف React را به گره‌ها و به‌روزرسانی‌های DOM وصل می‌کند. نام دقیق‌تر مسئول اعمال تغییرات DOM، React DOM است.
- DOM: ساختار فعلی سند در حافظهٔ مرورگر است. بعد از انتخاب، همان دکمهٔ HTML ویژگی و متن جدید دارد.
- CSS: تعیین می‌کند کلاس `is-selected` چه ظاهری داشته باشد؛ خود اضافه‌کردن یک کلاس، معنای رنگ سبز ندارد.
- Vite: ابزار توسعهٔ این مثال برای سرو فایل و تبدیل نحو است. تبدیل فایل لزوماً بررسی نوع نیست؛ این نمونه هنگام شروع، بررسی نوع را هم جدا اجرا می‌کند.
- Next.js: در این درس نیاز نشده و استفاده نشده است. در برنامهٔ بزرگ‌تر می‌تواند مسیرها، اجرای سرور، رندر اولیه و فرایند ساخت React را مدیریت کند. افزودن Next.js به معنی جایگزینی JavaScript، React یا JSX نیست.

## دو مرحلهٔ متفاوت: قبل از اجرا و هنگام اجرا

قبل از اجرا: کد TypeScript/TSX بررسی می‌شود؛ نوع‌ها حذف و JSX تبدیل می‌شود؛ مرورگر JavaScript قابل اجرا دریافت می‌کند. حذف نوع‌ها، منطق JavaScript داخل فایل را حذف نمی‌کند.

هنگام کلیک: مرورگر handler را اجرا می‌کند → شناسهٔ کتاب به `handleSelect` می‌رسد → setter درخواست تغییر state را ثبت می‌کند → React با مقدار تازه کامپوننت را دوباره اجرا می‌کند → `selected` تازه به کارت می‌رسد → JSX متن و کلاس مطلوب را توصیف می‌کند → React DOM تغییرات لازم را اعمال می‌کند → مرورگر ظاهر مناسب CSS را نمایش می‌دهد.

## آزمایش‌ها

۱. یک کتاب را انتخاب کن. در پنل state، `selectedId` را ببین. دکمه و پیام انتخاب عوض می‌شوند.
۲. «خواندن DOM» را بزن؛ دنبال `is-selected` و `aria-pressed="true"` بگرد. این خروجی یک snapshot است و فقط با زدن دوبارهٔ دکمه تازه می‌شود.
۳. تب «سورس TSX» را با «JavaScript تبدیل‌شده» مقایسه کن: `interface` و annotation پارامتر حذف شده‌اند، ولی تابع، شرط و داده‌های لازم وجود دارند. JSX به فراخوانی‌های `jsx`/`jsxs` تبدیل شده است.
۴. عبارت `React` را جست‌وجو کن؛ تعداد کارت‌ها یک می‌شود. عبارت `nothing-here` نتیجه‌ای ندارد. با خالی‌کردن ورودی، سه کارت برمی‌گردند.
۵. کتاب انتخاب‌شده را با جست‌وجو پنهان کن؛ انتخاب بالای صفحه باقی می‌ماند، چون state انتخاب از state جست‌وجو مستقل است. دوباره همان کارت انتخاب‌شده را بزن تا انتخاب پاک شود.
۶. صفحهٔ «بدون React» را باز کن و دکمه را بزن؛ همان متن و کلاس با دستورهای مستقیم DOM تغییر می‌کنند.

## چند تغییر برای دیدن مسئولیت‌ها

- در `books.ts` قیمت یا عنوان را تغییر بده: داده عوض می‌شود و خروجی مناسب می‌بینی.
- در `BookCard.tsx` عبارت انتخاب‌شده را تغییر بده: توصیف رابط عوض می‌شود.
- در `styles.css` رنگ `.is-selected` را تغییر بده: ظاهر عوض می‌شود، انتخاب و منطق آن ثابت می‌مانند.
- عمداً قیمت را در `books.ts` به رشته تبدیل کن و `check.mjs` را اجرا کن: TypeScript ناسازگاری را گزارش می‌کند. بعد مقدار را به عدد برگردان. ابزار تبدیل Vite به‌تنهایی جای این بررسی را نمی‌گیرد.
- مقدار اولیهٔ `selectedId` را در `App.tsx` از `null` به `"react"` تغییر بده: اولین نمایش هم کتاب React را انتخاب‌شده نشان می‌دهد.

## خروجی تبدیل‌شده و نکات اجرا

پوشهٔ `generated/` هنگام شروع سرور برای مقایسهٔ آموزشی با `typescript.transpileModule` ساخته می‌شود. فایل‌های آن داخل inspector به‌عنوان متن نمایش داده می‌شوند؛ صفحهٔ اصلی را Vite از سورس اجرا می‌کند و جزئیات خروجی dev آن متفاوت است. این خروجی مقایسه‌ای هنگام شروع ساخته شده؛ پس بعد از تغییر سورس، برای تازه‌کردن آن سرور را دوباره اجرا کن. ویرایش فایل generated، سورس کامپوننت را تغییر نمی‌دهد.

تازه‌سازی کامل صفحه state انتخاب و جست‌وجو را به مقدار اولیه برمی‌گرداند؛ ذخیرهٔ دائمی وجود ندارد. در این نمونه دیتابیس، پرداخت، حساب کاربری، درخواست API یا Next.js پیاده نشده‌اند.
