# فاز صفر: تثبیت مبنای انتشار چین‌ورس

تاریخ تثبیت: ۲۹ ژوئیه ۲۰۲۶

شاخه انتشار: `codex/release-phase-0`

مبنای ورودی: `2bc8a0a847ab0c124e016a9c6d1be928a1400d07`

این سند دامنه محصول را پیش از ادامه فازهای آماده‌سازی انتشار ثابت می‌کند.
هر مورد زیر یک گروه تغییر قابل پذیرش است؛ ریزآزمایی رفتاری هر گروه در فازهای
تخصصی بعدی ادامه پیدا می‌کند.

## دامنه دقیق ۲۹ تغییر

1. **CHG-01** نمایش و پنهان‌کردن رمز عبور در ورود و ثبت‌نام، بدون تغییر مقدار ورودی.
2. **CHG-02** نمایش لوگوی نوشتاری بزرگ چین‌ورس در مرکز سربرگ خانه، بدون متن یا آیکون تکراری.
3. **CHG-03** استفاده از نسخه و اندازه درست لوگوی نوشتاری در سربرگ پروفایل.
4. **CHG-04** استفاده از ذره‌بین برای کاوش و حذف نشانه قطب‌نما.
5. **CHG-05** یکسان‌سازی پس‌زمینه اصلی برنامه با `#FAFAFB`.
6. **CHG-06** متن راهنمای کامل «درباره من»، نمایش وب‌سایت‌ها هم‌سبک شبکه‌های اجتماعی و چینش justify.
7. **CHG-07** اصلاح متن «سوابق کاریتو اضافه کن» و آزادبودن عنوان شغلی رزومه.
8. **CHG-08** حالت خالی همسان و بدون تصویر برای درباره من، رزومه، گالری و خدمات.
9. **CHG-09** تغییر عنوان ورودی خدمت به «تصویر پوستر تبلیغاتی».
10. **CHG-10** نمایش کامل پوستر مربع یا مستطیل بدون برش اجباری.
11. **CHG-11** بزرگ‌ترشدن پوستر خدمت و جای‌گذاری درخواست مشاوره در سمت راست زیر «بیشتر».
12. **CHG-12** امکان ویرایش خدمت در کنار حذف.
13. **CHG-13** قرارگیری جزئیات زیر توضیح خدمت و لایک زیر جزئیات.
14. **CHG-14** راست‌چین‌شدن کپشن گالری و رفع مسیر بارگذاری تصویر.
15. **CHG-15** ترتیب و آیکون یکسان مکان و دنبال‌کننده در پروفایل شخصی و عمومی.
16. **CHG-16** بازگشت هر سربرگ پروفایل به حالت خالی واقعی پس از حذف همه محتوای آن.
17. **CHG-17** متن کامل حالت خالی اعلان‌ها مطابق طراحی.
18. **CHG-18** متن کامل حالت خالی پیام‌ها مطابق طراحی.
19. **CHG-19** بازشدن پیام‌ها پیش از تالار گفتگو و ثابت‌ماندن پشتیبانی پایین راست، بالای نوار ناوبری.
20. **CHG-20** ویرایش و حذف قابل اتکای سؤال‌های تالار گفتگو.
21. **CHG-21** جایگزینی HLS درس اول تلفظ با ویدیوی صحیح.
22. **CHG-22** همگام‌سازی زیرنویس فارسی، چینی و Pinyin همان درس.
23. **CHG-23** جاگرفتن کامل bottom sheetهای تنظیمات در viewport در زوم ۱۰۰٪.
24. **CHG-24** حفظ مسیر و درس ویدیو هنگام رفتن به تنظیمات ظاهر و بازگشت.
25. **CHG-25** حذف عکس پروفایل و نمایش آیکون پیش‌فرض نارنجی در نبود عکس.
26. **CHG-26** جنسیت، کشور/منطقه، استان شرطی ایران/چین و تأیید صحت اطلاعات در حساب کاربری.
27. **CHG-27** پشتیبانی یکسان از فرمت‌های رایج تصویر از جمله HEIC/HEIF در همه ورودی‌های عکس.
28. **CHG-28** روند یادگیری و هدف روزانه: متن قطره، انتخاب ۰ تا ۱۰۰ دقیقه، «سایر دقایق» و تصویر هدف.
29. **CHG-29** اصلاح ظاهر و نمایش، پیش‌فرض فاصله خطوط، متن درباره چین‌ورس و تأیید پیش از خروج.

## محیط‌ها

| محیط | وب | API | وضعیت ایندکس |
|---|---|---|---|
| staging فعلی | `https://chinverse.vercel.app` | `https://moamin9-chinverse-api.hf.space` | مسدود |
| production عمومی | هنوز ایجاد نشده | هنوز ایجاد نشده | فقط پس از تأیید نهایی فعال می‌شود |

`ENVIRONMENT=production` در API به معنی اجرای کنترل‌های امنیتی سخت‌گیرانه است.
وضعیت انتشار مستقل و با `DEPLOYMENT_TIER=staging` مشخص می‌شود. در وب نیز مقدار
پیش‌فرض `NEXT_PUBLIC_DEPLOYMENT_TIER=staging` است. تنها مقدار صریح
`production` اجازه index/follow می‌دهد.

## قابلیت‌های پنهان

| قابلیت | دلیل خاموش‌بودن | شرط فعال‌سازی |
|---|---|---|
| مدیریت اشتراک | درگاه پرداخت هنوز `manual-placeholder` است | درگاه واقعی، callback امن و آزمون پرداخت |
| دعوت دوستان | پاداش‌ها هنوز محاسبه و تسویه نمی‌شوند | قواعد پاداش، ضدتقلب و تست چرخه کامل |
| امتیازات | صفحه و قرارداد داده کامل نیست | مدل امتیاز، API و UI نهایی |

مقادیر پیش‌فرض feature flagها `false` است. منو، مسیر مستقیم وب و endpointهای
اشتراک و دعوت در حالت خاموش در دسترس کاربر نیستند.

## حریم خصوصی Git

- ۲۸ فایل runtime شامل ۱۲ آواتار، ۱۰ تصویر گالری و ۶ پوستر خدمت از tree حذف شد.
- هفت ایمیل/نام مشخص از migration قدیمی پاک شد و revision برای حفظ زنجیره no-op ماند.
- مسیرهای `backend/uploads/` و `backend/static/uploads/` در `.gitignore` هستند.
- `scripts/check-release-baseline.ps1` در CI بازگشت فایل‌های runtime یا env خصوصی را متوقف می‌کند.
- تاریخچه شاخه‌ها باید پیش از push نهایی بازنویسی و remoteها با
  `--force-with-lease` به‌روزرسانی شوند؛ شناسه commit نهایی پس از این کار مرجع deploy است.

## معیار خروج فاز

1. guard مبنا، تست‌های frontend/backend، build و مرورگرها سبز باشند.
2. هر دو health endpoint محیط `staging`، نسخه release و noindex را گزارش کنند.
3. GitHub، Vercel و Hugging Face به commitهای ثبت‌شده در گزارش نهایی اشاره کنند.
4. production عمومی ایجاد یا indexable نشود.

## ممیزی اجرایی تکمیلی — ۲۴ اوت ۲۰۲۶ (پیش از مجوز rewrite)

این سند baseline تاریخی فاز صفر است؛ وضعیت اجرای فعلی در
`docs/LAUNCH_READINESS_ACTION_PLAN_FA.md` ثبت می‌شود. در ممیزی تکمیلی:

- guard tree-level privacy و release سبز است؛ فایل‌های runtime، env خصوصی و
  artifact دیتابیس در tree فعلی tracked نیستند. strict history guard عمداً fail
  می‌شود، چون دو commit قابل‌دسترسی هنوز migration قدیمی display-name را دارند.
- frontend و backend قرارداد staging/noindex و featureهای ناقص را enforce می‌کنند؛
  backend `/health` نیز اکنون `indexable` را صریحاً گزارش می‌کند.
- deploy workflow دیگر به branch بازنشستهٔ فاز ۷ قفل نیست و SHA را نسبت به
  `release_ref` بررسی می‌کند.
- commit فاز ۸ هنوز روی remote/main نیست و live deployment با همان SHA ثبت نشده است.
- history قابل‌دسترسی هنوز یک migration قدیمی با دادهٔ display-name دارد؛
  history rewrite و force-push فقط پس از تأیید مالک پروژه انجام می‌شود.

بنابراین اصلاحات کدی فاز صفر انجام شده، اما این بخش از گزارش مربوط به وضعیت قبل
از دریافت مجوز rewrite است. الحاقیهٔ اجرایی زیر وضعیت فعلی را ثبت می‌کند.

## الحاقیهٔ اجرایی پس از rewrite — ۲۴ اوت ۲۰۲۶

- history تمام refهای publishable بازنویسی شد و migration قدیمی به revision
  no-op تبدیل شده است؛ `git grep --all` برای داده‌های شخصی و
  `DISPLAY_NAME_UPDATES` در refهای قابل‌دسترسی پاک است.
- شاخه‌های phase 2 تا phase 8، `codex/release-phase-0` و `main` با
  `--force-with-lease` روی remote ثبت شدند. HEAD مستندات شاخهٔ phase 8 برابر
  `966b4340545374db03c718657f9fe4bd5c143aba`، آخرین SHA کد/CI-tested برابر
  `7238566467d821bd9acce70a6bf7441a06a2cd16` و SHA `main` برابر
  `bd7b016edede215885f495370b1976a230d3a996` است؛ remote tag وجود ندارد.
- bundle پیش از rewrite برای بازیابی محلی در
  `.backups/phase0-history-rewrite-20260824/before.bundle` نگه‌داری شده و
  به remote منتقل نشده است.
- health زنده هنوز deploy همان SHA phase 8 را اثبات نمی‌کند: frontend روی
  `bd7b016...` و backend روی `3b3a918...` است. ruleset/required checks نیز باید
  از حساب صاحب repository ثبت و قابل‌مشاهده شود.
